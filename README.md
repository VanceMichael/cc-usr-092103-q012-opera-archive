# 晋戏影像史料审定

整理戏曲影像、人物、剧种和史料说明的审定规范。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同标识和版本约定。

当前资料反映的事实包括：

- 资料覆盖三十八个剧种
- 影像同时记录台前与幕后
- 每幅影像需要配套源流和人物资料

## 审定后台

`src/archive/` 是审定后台的领域服务层，覆盖《晋戏》二十多年资料的登记、审定、发布与追溯。`fixtures/archive.sample.json` 给出样例资料（三十八个剧种的源流、地点、戏班、剧目、多名异名的艺人样例、拍摄批次、影像、许可与身份争议），`contracts/archive.schema.json` 描述其结构约定，`src/archive/loader.js` 负责装载。

### 模块

- `store.js` 内存仓库与标识、序号约定
- `catalog.js` 剧种（源流）、剧目、戏班、地点、艺人（一人多名，各名带来源）、专家、拍摄批次登记
- `images.js` 原始影像登记与派生件（编辑稿）挂接
- `captions.js` 说明文字版本与审定
- `corrections.js` 事实更正（来源 + 相应专家签署）
- `disputes.js` 身份争议与各说法来源
- `merges.js` 重复底片与同人异名归并
- `licenses.js` 许可版本与四渠道授权范围
- `publishing.js` 发布、撤回、公众视图、研究视图
- `trace.js` 已发布影像的追溯链

### 不变量

1. **原照片不得被编辑稿替换**：原件登记即冻结，裁剪、修复、压缩等编辑稿只能作为派生件挂接；归并重复底片时原件也保留在库。
2. **事实更正须附来源并取得相应专家签署**：无来源拒绝登记；未签署不得生效；专家专长不覆盖目标剧种（或影像领域）拒绝签署。前后值都留档。
3. **归并必须解释依据**：重复底片与同人异名可以归并，但无依据拒绝；异名连同各自来源并入留存档案，被归并的档案与原件保留备查。
4. **发布绑定版本**：发布记录固定当时的说明文字版本与许可版本，之后文字或许可再变，历史发布仍能追到当时版本。
5. **公众与研究分视图**：公众视图只给许可允许的照片与已审定文字；研究视图同时呈现原始影像、各说法来源、未决争议与审定过程。
6. **不确定性不被抹平**：说法全部带来源留档，争议了结后各说仍保留；发布文字可附存疑提示随版本给出。

### 渠道授权

展览（exhibition）、出版（publication）、研究下载（research）、青少年传播（youth）四个渠道各自执行自己的授权范围，每渠道取值 `allow` / `conditional` / `deny`；`conditional` 放行时条件写入发布记录。许可按版本登记，旧版本留档。
